# Phase 1 (QNX 8.0 Trace Format &) Verification Table Findings

| # | Question | Answer | Evidence |
| --- | --- | --- | --- |
| **1** | How is tracing enabled on QNX 8.0, and is a special kernel needed? | **No special kernel build is needed.** The default `mkqnximage --type=qemu` image boots `/proc/boot/procnto-smp-instr` (the instrumented SMP microkernel) out of the box. Tracing is enabled by running `tracelogger -w -s <seconds> -f <file.kev>` as `root`. | `inversion_spike_clean.txt` header & event 10: `name:/proc/boot/procnto-smp-instr` (`pid:1`) and `TRACE_TRACELOGGER_ARGS:: tracelogger -w -s 3 -f /tmp/inversion_spike.kev`. |
| **2** | Does `traceprinter` run on the host, or only on the target? | **Runs natively on the Pop!_OS Linux host** (`$QNX_HOST/usr/bin/traceprinter`) as well as on the target. *(Note: Do not pass `-v` to `traceprinter`, as it dumps raw `TRACEPARSER` debug lines; pass `-w` to `tracelogger` instead.)* | `TRACEPRINTER version 1.02` / `TRACEPARSER LIBRARY version 1.02` executed directly on the Pop!_OS host to produce `inversion_spike_clean.txt`. |
| **3** | Does the text output contain thread names, priorities, thread states, CPU numbers? | **Yes, when captured with `tracelogger -w` (wide mode).** Every `THREAD` event logs `CPU:xx`, state name, `pid:`, `tid:`, `priority:`, and `policy:` on the same line. Process and thread names are emitted in multi-line `PROCESS :PROCCREATE_NAME` and `PROCESS :PROCTHREAD_NAME` events. | `t:0x18cdadd3cf48 CPU:01 THREAD :THRUNNING pid:1404944 tid:4 priority:40 policy:1` and `PROCESS :PROCTHREAD_NAME pid:1404944 tid:4 name:sensor_high`. |
| **4** | Does a mutex-blocked event identify the lock owner? | **Yes, in wide mode (`tracelogger -w`).** Uncontended mutex locks use a user-space fast-path, but whenever a thread blocks on a locked mutex, `KER_CALL :SYNC_MUTEX_LOCK/80` logs `sync_p` (mutex address) and `owner`. The lower 16 bits (`owner & 0xFFFF`) contain the owning thread's `tid`. | `KER_CALL :SYNC_MUTEX_LOCK/80 sync_p:0x000000501106c010 count:-1879048192 owner:1880096770` (`1880096770` = `0x70100002` $\rightarrow$ lower 16 bits = `tid:2` `logger_low`). |
| **5** | What are tracing overhead and file size for a 30 second capture? | **Low overhead and manageable size.** In wide mode (`-w`), QNX records 16-byte binary events in 1,011-event (~16 KB) buffers. A 3-second capture produced ~4 buffers (~65 KB `.kev`, ~600 KB `.txt`). A 30-second capture scales linearly to **~650 KB – 2 MB `.kev` (~6–15 MB `.txt`)**, which Python parses in `< 0.5 seconds`. | `inversion_spike_clean.txt`: `TRACE_ENCODING:: 16 byte events`, `CONTROL :BUFFER sequence = 1..4, num_events = 1010` across `CPU:00` and `CPU:01`. |
| **6** | Can Eclipse Trace Compass headless read the trace? (time-box: 2 hours) | **Skipped / Not needed.** `traceprinter` on the host outputs deterministic, human-readable text that our custom Python parser (`src/timingguard/ingest.py`) ingests in `< 0.15s` with zero external Java/Eclipse dependencies. | `src/timingguard/ingest.py` parses `inversion_spike_clean.txt` directly using standard library Python. |
| **7** | Do the exact state names (`THRUNNING`, `THREADY`, `THMUTEX`, `THSEM`, `THSEND`, `THREPLY`) appear as assumed? | **Yes.** All core state names match `THREAD :<STATE>`. Observed states in traces: `THRUNNING`, `THREADY`, `THMUTEX`, `THMUON_MUTEX`, `THSEM`, `THRECEIVE`, `THREPLY`, `THSEND_NOTIFY`, `THNANOSLEEP`, `THCONDVAR`, `THJOIN`, `THSIGWAITINFO`, `THSIGSUSPEND`, `THINTR`, `THCREATE`, `THDESTROY`, `THDEAD`. | Verified directly in `sample_001.txt` and `inversion_spike_clean.txt` under the `THREAD` class column. |
| **8** | Can user markers be inserted into the trace (for example through `TraceEvent` or `trace_logf`)? | **Yes.** Enabling user events via `TraceEvent(_NTO_TRACE_ADDCLASS, _NTO_TRACE_USER)` and calling `TraceEvent(_NTO_TRACE_INSERTUSRSTREVENT, id, str)` emits `USREVENT :EVENT:<id> STR:"..."`. *(Note: x86_64 swaps 2-byte pairs in `USRSTREVENT` strings, e.g., `"sesnro_high"`; we can unswap pairs in Python or use integer `INSERTUSREVENT`.)* | `t:0x18cdadd3e013 CPU:01 USREVENT :EVENT:101 STR:"tg_job_end:sesnro_high", d0:0x6a5f6774...` in `inversion_spike_clean.txt`. |
| **9** | Does the QNX image boot under KVM? | **Yes.** `/dev/kvm` is enabled on the Pop!_OS host (`kvm-ok` passed) and the 2-CPU x86_64 QNX image runs at native host clock frequency (`2,495,955,300` cycles/sec $\approx$ 2.50 GHz). | `inversion_spike_clean.txt` header: `TRACE_CYCLES_PER_SEC:: 2495955300`, `TRACE_CPU_NUM:: 2`, `TRACE_MACHINE:: x86pc`. |
| **10** | Which events does the trace carry for CPU affinity, priority changes and interrupts? | **All three are explicitly logged:**<br><br>• **CPU Affinity:** `KER_CALL :THREAD_CTL/52` (`cmd:0x4` = `_NTO_TCTL_RUNMASK` with `data_p` bitmask) plus `CPU:00`/`CPU:01` on every event.<br><br>• **Priority Changes:** Logged inline (`priority:<int> policy:<int>`) on every `THREAD` state event in `-w` mode.<br><br>• **Interrupts:** `SYSTEM :IST_ATTACH`, `INTERRUPT :INT_DELIVER intr_id:...`, and `THREAD :THINTR`. | `KER_CALL :THREAD_CTL/52 cmd:0x00000004`, `INTERRUPT :INT_DELIVER intr_id:0x80010000`, and inline `priority:40 policy:1` in `inversion_spike_clean.txt`. |
